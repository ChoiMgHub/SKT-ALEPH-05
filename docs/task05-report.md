# 과제 05 — 대화가 끊겨도 이어지는 프로젝트

## 이번에 한 작업
과제 03의 짤·카드 스튜디오를 바탕으로 저장된 템플릿의 이름 검색 기능을 추가했다. 이번에는 기능을 크게 늘리기보다, 다른 AI가 이전 대화를 읽지 않아도 코드와 문서만으로 작업을 이어갈 수 있는지 확인하는 데 집중했다.

검색은 제목의 일부로 찾고, 앞뒤 공백과 영문 대소문자를 처리한다. 검색창이 비어 있거나 공백만 있으면 전체 목록을 보여준다. 결과가 없으면 안내 문구를 표시하고, 초기화 버튼을 누르면 전체 목록으로 돌아온다. 검색 때문에 저장 데이터가 바뀌지 않는 것도 완료 조건에 넣었다.

## 같은 조건으로 비교한 결과
구현 전에 고정 검사 10개와 각 AI의 최대 30분·8회 요청 제한을 정했다. 요청 메시지와 재생성을 각각 1회로 세며, 오류 회차는 고정 검사 10개 중 하나 이상이 FAIL인 실행 회차로 센다.

| 항목 | AI A | AI B |
|---|---|---|
| 실제 작업 시간 | 사용자 기록 18분 | 미확정 — 실제 시작·종료 시각 확인 필요 |
| 실제 요청 수 | 사용자 기록 1회 | 사용자 기록 1회 |
| 고정 검사 실행 회차 | A-1, 1회 | B-1 원본 / B-2 수정본, 2회 |
| 검사 통과 수 | 10/10 | 원본 10/10, 수정본 10/10 |
| 오류 회차 수 | 0회 | 0회 |
| 검사 수행 | 학생의 로컬 브라우저 수동 검사 | B가 새 작업 폴더의 브라우저에서 직접 실행했다고 보고 |
| 역할 | 이름 검색 기능의 첫 구현 | 문서만으로 재현·검토하고 이름 표시 문제 최소 수정 |

검사 삭제·약화·기대 결과 변경은 없다. B의 두 회차도 같은 고정 검사 10개를 사용했으며, 이를 서로 다른 검사 20개로 세지 않았다. 서버 연결 시행착오와 PNG 다운로드 관찰 시간 초과는 고정 검사 FAIL 회차에 포함하지 않았다.

B의 실제 시간이 확인되지 않아 시간 제한 준수와 시간 비교는 아직 확정하지 않았다. A와 B는 맡은 단계가 다르므로 이 표만으로 어느 모델이 더 우수하다고 결론 내리지 않는다. 비교표에는 서비스·모델 이름을 표시하지 않았다. 서로 다른 서비스 또는 모델 사용 조건은 실제 사용 정보를 확인해 최종 점검한다.

## 작업 순서와 코드 버전
| 단계 | 기록한 소스 버전 |
|---|---|
| A 시작 | `32f623fb22b4ac8ce6c5d484edb83962d3b1e163` |
| A 종료 | `da390b53b1f020bb532dfad51d77175bf99f0b47` |
| B 시작 | `da390b53b1f020bb532dfad51d77175bf99f0b47` — 최신 문서는 로컬 파일로 함께 전달 |
| B 종료 | 미커밋 수정본 — B 결과를 커밋한 뒤 전체 커밋 번호로 교체 필요 |

B 시작 index.html SHA-256: `E0313CB3C0936E068745B53755E201F8164596B618494CD701C4C467091CFC14`.

B 수정본 index.html SHA-256: `73518B8A32F84F714631D133BF02D2964A8E10793DE175A29C9C72C41CC92C03`.

재작업량은 임의의 숫자로 적지 않았다. 네 단계의 고정 커밋을 보존하고, 제출 측에서 생성 파일·lockfile을 제외한 소스 추가·삭제 줄 수를 계산하도록 한다. B 종료 커밋은 제출 전에 확정해야 한다.

## 인수인계에서 보완한 내용
B에게는 코드와 인수인계 자료를 전달했고 A와의 대화 전문은 전달하지 않았다. B는 제공된 다섯 파일을 새 작업 폴더에 복사해 시작 코드의 해시를 확인했다. 기존 개인 데이터가 있는 주소를 변경하지 않고 별도 포트인 `http://127.0.0.1:8016/`에서 검사했다.

처음 인수인계 문서에는 기준 버전 자리표시자가 남아 있었다. Python 사전 조건, 새 폴더 준비와 버전 고정, 로컬 최신 문서의 별도 전달, 포트와 브라우저 저장 데이터 분리, 검사 전후 JSON 비교 방법도 보완했다. 누락과 보완 내용은 [작업 기록](task05-work-log.md)과 [B 검토 결과](task05-ai-b-review.md)에 남겼다.

## B가 최소 수정한 부분
검색은 원래 고정 검사에서 모두 통과했다. B는 별도 확인 중 `Ops <b>Card</b> "Q"`라는 이름이 HTML로 해석되어 화면 표시가 달라지고 버튼의 접근성 이름도 잘리는 문제를 보고했다.

이름과 버튼을 만드는 부분만 `createElement`, `textContent`, `dataset`, `setAttribute`로 바꿨다. 검색 규칙과 저장 키, 템플릿 객체 형식, 편집·저장·불러오기·수정·삭제·JSON 처리는 변경하지 않았다. 수정 후 같은 고정 검사 10개를 다시 실행한 결과도 10/10 PASS로 기록됐다.

## 데이터 보존 증거
[검사 전 JSON](../baseline-templates.json), [B-1 검사 후 JSON](../B-1-after-templates.json), [B-2 검사 후 JSON](../B-2-after-templates.json)은 파일 바이트가 동일하다. 기본 세 템플릿의 이름뿐 아니라 모든 필드가 유지됐다.

세 파일의 SHA-256: `92B20D771A5A8CE24BD1E9AA630A9EC21D83DC5503E5E07C00167945DCA83FF9`.

[최종 화면](../B-final-search.jpg)에는 보안 검색 결과 한 개와 불러온 기본 문구·1:1 비율이 보인다. 이 화면 한 장으로 모든 검사를 통과했다고 판단하지 않고 개별 실행 기록과 JSON 증거를 함께 남겼다.

## 아직 확인하지 않은 부분
PNG 다운로드 파일의 실제 생성·해상도와 PNG/JPEG 배경 업로드는 학생 수동 확인 결과를 추가해야 한다. 손상 이미지, 모든 스타일 조합과 다른 브라우저는 미검증이다. 기존 JSON 타입·허용값 검증 부족과 손상된 localStorage 복구는 이번 검색 기능 범위에서 수정하지 않았다.

이 문서에서 미확정인 B 시간·종료 커밋과 수동 확인 결과는 제출 전 실제 값으로 보완한다. 미확정 상태를 완료로 표시하지 않는다.

## 빠른 확인 방법
어디로 가나요: 제출한 소스 커밋의 index.html이 있는 저장소 루트로 간다.

무엇을 하나요(3단계 이내): ① `python -m http.server 8016 --bind 127.0.0.1` 실행 ② 개인 데이터가 없는 비공개 창에서 `http://127.0.0.1:8016/` 접속 ③ 기본 세 템플릿을 확인하고 `보안` 검색 후 불러오기를 누른다.

무엇이 보이면 통과: 보안 제목 한 개만 표시되고, 불러오기 후 기본 보안 문구와 1:1 비율이 적용된다. 전체 완료 판정은 고정 검사 10개와 전후 JSON 비교 결과로 확인한다.

안 될 때: 서버 시작·접속·기본 데이터 준비가 안 되면 검사 준비 실패로 기록한다. 실행된 고정 검사에서 기대 결과와 다르면 해당 검사 FAIL을 기록하고, 오류와 재현 절차를 남긴다.

## AI와 내가 맡은 일
AI에게 맡긴 일: 이름 검색 기능 구현, 문서 기반 재현·검토, 특수문자 이름 표시 문제 최소 수정과 검사·문서 보완.

내가 판단한 일: 과제 03의 이름 검색으로 범위를 정하고, 구현 전 검사 10개를 고정했다. A의 수정본을 직접 검사하고 Git 명령어로 작업 버전을 남겼다.

AI 말을 안 들은 일: 별도로 거절한 구현 제안은 없었다. 원래 목표 안의 수정만 진행했으며, B가 확인하지 못한 다운로드·업로드는 통과로 적지 않고 별도 확인 대상으로 남겼다.

## 다음 작업에서 사용할 기준
작은 기능 구현에는 A처럼 첫 구현을 맡기고, 작업을 이어갈 때에는 B처럼 문서만으로 실행 가능한지와 기존 동작이 유지되는지를 먼저 확인하는 방식으로 진행하겠다.
