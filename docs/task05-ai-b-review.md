## 결과

## 직접 실행 결과
- 새 폴더로 제공 파일을 복사하고 원본 index.html 해시 일치를 확인했다. 빌드 없이 Python HTTP 서버로 실행했다.
- 8000번에는 기존 데이터가 있어 변경하지 않았다. 분리된 `http://127.0.0.1:8016/`에서 기본 세 템플릿으로 실행했다.
- B-1: T05-01~T05-10 각각 PASS. B-2: 같은 ID·입력·기대 결과의 10개 각각 PASS.
- 검사 전, 원본 검사 후, 수정본 검사 후 실제 내보낸 JSON 세 파일의 SHA-256은 모두 `92B20D771A5A8CE24BD1E9AA630A9EC21D83DC5503E5E07C00167945DCA83FF9`다. 세 항목과 모든 필드가 유지됐다.
- 별도 보완 확인: 영문 대소문자, 본문 제외, 특수문자 이름, 임시 템플릿 저장·수정·불러오기·삭제, 정상 JSON 복원, 문법 오류·필수 속성 누락 JSON 거절, 문구·비율·정렬·배너의 화면 반영. 고정 검사 개수에 합산하지 않았다.
- PNG 다운로드 완료 관찰은 자동화 시간 초과로 미완료다. 배경 이미지 업로드도 직접 완료하지 않았다. 이 항목을 PASS로 기록하지 않았다.

## 코드 변경
문제는 `Ops <b>Card</b> "Q"`라는 이름을 직접 저장·검색해 재현했다. 원본은 이를 HTML로 해석해 화면 이름을 `Ops Card "Q"`로 바꾸고 버튼의 aria-label을 중간에서 잘랐다. 이는 저장된 이름과 화면 표시가 달라지는 기존 목록 렌더링 문제다.

전체 재작성 없이 목록의 span·버튼 생성 부분만 createElement/textContent/dataset/setAttribute로 바꿨다. 제목과 ID는 값으로 전달되며 HTML로 해석되지 않는다. 저장 데이터의 이름·ID·필드·키를 바꾸지 않는다. 검색 규칙과 편집·CRUD·JSON 처리 코드는 그대로다.

- 시작 index.html SHA-256: `E0313CB3C0936E068745B53755E201F8164596B618494CD701C4C467091CFC14`
- 종료 index.html SHA-256: `73518B8A32F84F714631D133BF02D2964A8E10793DE175A29C9C72C41CC92C03`
- 전체 수정 파일: 묶음 루트의 `index.html`.

## 남은 문제·수동 확인
- 고정 10개에서 확인된 실패는 없다.
- PNG 다운로드 파일의 실제 생성·해상도, PNG/JPEG 배경 업로드, 손상 이미지 처리, 모든 스타일 조합과 다른 브라우저는 수동 확인이 필요하다. 다운로드 자동화가 완료되지 않은 것을 앱 자체 결함으로 단정하지 않는다.
- 정적 검토상 기존 JSON 검사는 필수 키 존재 위주이며 타입·ratio 허용값 등의 검증이 부족하다. 잘못된 값과 손상된 localStorage는 직접 실행하지 않았다. 이번 검색·이름 표시 최소 수정 범위에서 변경하지 않았다.
- Git 커밋·푸시는 하지 않았다. HANDOFF와 B 수정 내용의 원격 공유에는 전달 묶음 또는 별도 커밋이 필요하다.
- A 서비스/모델 정보 누락으로 계획의 A/B 서로 다른 서비스/모델 조건은 문서만으로 확인할 수 없다.
